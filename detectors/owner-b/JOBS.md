# Background jobs and scheduling (Group 3)

Defines the Group 3 interfaces for #180 JOB-01, #181 JOB-03, #182 JOB-04, #183 JOB-05 and #184 JOB-06 through the shared contract v1. Each implemented check is added to the public `evaluate(input)` registry and CLI alongside all four database checks. Nothing imports or executes customer code. These checks diagnose inefficiency; they do not change jobs, worker capacity or customer queues.

Run `npm ci`, `npm run lint`, `npm run typecheck`, `npm test` and `npm run build:owner-b`. Python contract dependencies must be installed; `G01_PYTHON` can select the existing validator environment. CI already runs the Owner B test glob and the shared Python contract suite. Unit fixtures identify themselves as synthetic; they prove algorithms, not production waste.

## Inputs and evidence

Every input uses `detector_version: "1.0.0"`, context `rule_version: "jobs-1"` and explicit `mode: "candidate"` or `"runtime"`. Scope units are a complete pool inventory, worker pool, job or route. Missing, unsupported or incomplete evidence yields unavailable/partial coverage with reasons; it never means zero waste. Identity is stable across line movement, changing observations, scans and commits. Result measurements stay empty: these algorithms do not measure electricity, carbon or attributable CPU.

| Check | Required sources | Context | Evidence level |
| --- | --- | --- | --- |
| JOB-04 | One complete `schedule-inventory-v1` JSON source or artifact | `horizon: {start,end}` (at most seven days); integer `max_occurrences` 1–2000 | Possible coincident starts/overlap on shared constrained capacity, not observed load spikes |
| JOB-03 | `worker-capacity-v1` telemetry with complete acquisition and reviewed capacity policy | `minimum_window_seconds` at least 3600; `max_busy_fraction` 0–0.2; runtime mode | Sustained application occupancy versus provisioned workers and required reserve; not hardware CPU |
| JOB-05 | `job-runs-v1` telemetry with complete acquisition and reviewed input boundary | integer `minimum_runs` 2–100; `minimum_work_units` at least 1; runtime mode | Repeated successful full work on unchanged relevant inputs |
| JOB-01 | JavaScript ES2022 source and reviewed `request-work-v1` artifact; correlated `request-observations-v1` for runtime | `minimum_requests`, `minimum_operation_ms` for runtime | Source-only findings are explicitly static candidates; runtime requires attributable spans |
| JOB-06 | Same source/metadata plus request observations and a complete deployment interaction inventory | `minimum_requests`, `minimum_peak_mean_ratio`, `minimum_backpressure_ms` | Architecture candidate requiring separate human review, even with runtime evidence |

Complete examples are in `test/jobs-fixtures.js`; each factory produces the exact shared envelope and normalized formats. All nonstatic observations carry matching `repository_id` and `commit_sha`. A connector must map existing telemetry to the declared source snapshot; it must not relabel an unrelated deployment's observations as this commit. Acquisition `start/end` timestamps must include a timezone. Missing samples/counters remain unknown.

Schedule records require stable `job_id`, `pool_id`, `pool_capacity`, `slots`, `enabled`, `expression`, `dialect`, `timezone`, `flexible_window_seconds`, `jitter_seconds`, `intentional_alignment` and `serialized`. Optional `duration_seconds` supports overlap candidates; without it only coincident scheduled minutes are detected. Disabled jobs are excluded. Independent pools, intentional alignment, enforced serialization and sufficient capacity suppress findings. The bounded pairwise algorithm does not detect aggregate overload from three or more individually compatible jobs.

Supported schedules: numeric POSIX five-field cron, and an explicit AWS Scheduler subset: six fields with wildcard year, exactly one `?` day field, numeric date/month and single numeric weekday. AWS hour/minute fields support literals or `*`; `L`, `W`, `#`, named fields, year constraints, `at(...)` and unsupported dialects are unavailable. AWS rates require a known timezone-qualified start anchor and valid singular/plural units. Rate days are fixed 24-hour intervals. AWS cron skips nonexistent spring-forward times and invokes once on fall-back. Flexible windows/jitter yield unavailable collision coverage rather than a deterministic execution-time claim. Start/end constraints and a duration lookback handle overlap across the horizon boundary; recurrence expansion is bounded.

Worker observations require aligned complete samples (`timestamp`, `workers`, `busy_worker_seconds`, `queue_depth`, `arrivals`). Capacity policy names minimum and burst-reserve workers, shared workloads, leader/heartbeat duties and cold-start tolerance. Low CPU or an empty queue alone is insufficient. The CloudWatch adapter reads explicitly configured application occupancy metrics with units/statistics; ordinary AWS Lambda Duration cannot substitute for busy-worker seconds. It validates dimensions, pages and full coverage. Queue depth uses Maximum to preserve a burst within a period; capacity uses Average, busy seconds/arrivals use Sum.

Job observations require unique run IDs, successful first attempts, full-work flags, positive observed work, identical relevant input and output versions, consistent work units, chronological non-overlap and a reviewed cheap change detector. Time/external-state tasks, reconciliation, incomplete input boundaries, unsafe hashes, retries and failures suppress findings. Equal output alone is insufficient. Work units remain exact evidence and are not converted to CPU savings.

Request analysis supports a unique top-level named function (optional named export) with straight-line const/direct/awaited calls and a final response call. It rejects branching, early returns, aliases, computed calls, nested callbacks/calls and unsupported syntax. Reviewed metadata declares handler, operation, response API, urgency/transaction requirements, exact source digest and deployment interaction inventory. This is a bounded direct-call model, not an interprocedural framework scanner. Comments/strings do not count as calls. An awaited expensive optional operation is a candidate; async syntax alone does not make heavy work harmless. Runtime spans must finish before the response and match route, operation, repository, commit and source digest. No automatic queue is introduced.

## Real AWS deployment

The selected integration Region was changed by the user to **ap-south-1 on 2026-10-10** to join the shared project. Use `infra/owner-b/jobs.cjs`, which requires that Region explicitly and a verified project identity. Existing eu-north-1 resources are historical and are not silently moved or destroyed. The new stack has private encrypted versioned artifacts, Node 22 ARM64 static/log/telemetry/heuristic functions, separate least-privilege roles and failure queues, seven-day operational logs, seven-day inputs and thirty-day results. No public function URL or customer resource writes are created. The build bundles all dependencies.

Deploy immutable S3 code versions through inspected CloudFormation change sets. Verify the function code hash and published version against the clean committed build. Invoke deployed functions, validate actual input/result pairs and read immutable S3 artifacts back. `family: "jobs"` is required when invoking static/log through an S3 input pointer; direct envelopes dispatch on check ID. Duplicate invocations converge on the same content-addressed result.

Server-side allowlists configure `WORKER_POOLS`, `JOB_LOG_SOURCES` and `SCHEDULE_GROUPS`; invocation payloads cannot grant themselves access. `event.acquisition` supplies only an approved pool/job/group and bounded window. Existing Scheduler inventories are listed then individually described. CloudWatch metrics are paginated; Logs Insights queries poll to a terminal status, reject truncation and cancel abandoned queries. Missing configuration/acquisition returns unavailable. Occupancy/response semantics are connector assertions requiring review. For JOB-01/JOB-06 a connector submits an existing correlated trace artifact; no runtime trace is invented or produced by executing customer code.

Results are pair-validated before storage/publication. The existing shared EventBridge bus accepts `DetectorResultPointer.v1` events from `owner-b.detectors`. An accepted event does **not** prove ingestion: at discovery the shared bus had no rules or writer target. Owner D must supply compatible pointer ingestion and persisted report readback. JOB-06 also needs the separately recorded business review. Public source scans cannot runtime-confirm JOB-03/JOB-05/JOB-06; JOB-01 emits only labelled candidates without observations. No issue is called fully AWS accepted while these gates remain missing.

## Research references

The implementation uses a bounded parser and original detection rules. Design references: [AWS Scheduler timing and DST](https://docs.aws.amazon.com/scheduler/latest/UserGuide/schedule-types.html), [cron-parser's documented timezone interface](https://github.com/harrisiirak/cron-parser), [Node.js event-loop guidance](https://nodejs.org/en/learn/asynchronous-work/dont-block-the-event-loop), and [AWS transactional outbox](https://docs.aws.amazon.com/prescriptive-guidance/latest/cloud-design-patterns/transactional-outbox.html). Messaging advice includes idempotency, ordering, bounded retries, dead letters and atomic state/enqueue behavior. It remains conditional on business semantics.

## Publication and provenance rules

One issue per branch and incremental commit; dependent changes use a linear stack retaining every earlier registry entry. No duplicated independent foundation copies. Rebase the next dependent branch after each squash merge. Public receipts contain only checks, results, code/context/lock hashes, clean build commit and explicit limitations. Raw project IDs, ARNs, team-member IDs, profiles, buckets, stack names, request IDs and query IDs stay in ignored private records. Sanitized pairs have separately labelled public hashes; they are not claimed byte-identical to private S3 pairs. Commit messages use the repository convention and omit all assistant co-author trailers. No independent reviewer approval is fabricated.
