# Network, API and serialization checks

Group 2 is read-only. The auditor parses supplied source, snapshot-correlated X-Ray metadata, HTTP records and client-produced benchmark/profile/HAR artifacts. It never executes customer code or starts a customer's browser. CodeBuild browser execution is replaced by client-captured HAR ingestion under the approved read-only architecture.

Every check requires contract v1 input, detector version 1.0.0, context.rule_version network-1 and explicit candidate/runtime mode. One scope is one route/message operation. Structured sources use format network-evidence-v1 and repository_id/commit_sha identical to the envelope, a complete acquisition window, and capture tool/version/origin. Capture origins are synthetic, client or auditor. Synthetic records test behavior and transport only. Connector assertions are not independently authenticated workload facts.

Core adapters enforce evidence, coverage and semantic fingerprints. Unsupported formats, incomplete captures and absent required fields produce unavailable/partial, never a clean runtime scan. No energy, carbon or projected savings are generated. Findings cite exact supplied top-level fields. Runtime confirmation requires genuine client captures and, for architecture changes, separately recorded human review.

AWS uses three separate functions: owner-b-trace-analyzer (X-Ray/metric acquisition and network analysis), owner-b-profile-parser (client artifact ingestion and network analysis), and owner-b-network-upload (authenticated connector upload signing). Existing jobs functions are preserved. The protected same-Region artifact bucket and Owner D hub are reused. Result pairs are validated in deployed code, content-addressed, conditionally written and published as allowlisted pointers. Only report readback establishes persistence.

The upload signer is available only to IAM-authorized callers and enforces a server repository allowlist, 1 MiB limit, SHA256 checksum, conditional create and a 5-minute URL. It grants PUT only. The client uploads a complete normalized contract input, not executable code. Input versions are immutable; S3 ObjectCreated notifications for inputs/network/ invoke the parser. Failed events retry with a DLQ; result prefixes cannot retrigger parsing. Replay converges on one result pair.

X-Ray collection uses a server-configured filter, a <=1-hour window, <=20 summary pages, <=50 traces, five IDs per full-trace request, timeouts and explicit unprocessed handling. Segment metadata.owner_b must carry the repository/commit, route operation and required check semantics; ordinary X-Ray spans lack consumer dependencies, field use and batch API availability. They cannot be filled by guessing. CloudWatch uses server-configured exact metric definitions and aligned windows; absent points remain missing. IAM scopes acquisition to the selected Region.

See checks/net-*/SPEC.md for each supported rule, evidence fields, thresholds, cases and exceptions. Client exports are documented with the artifact formats and tests. Public source-only analysis is a candidate where supported, not runtime confirmation.

The repository scan adapter lists registered NET checks as unavailable when a public source scan lacks runtime captures, route mappings and reviewed policy metadata. It does not execute client code to create those captures. The authenticated artifact connector supplies the full network detector interface independently of that source-only scan.

## Deployment and reproducibility

Install the locked root dependencies, then run `python scripts/package-owner-b-network.py` from clean committed source. The archive contains exactly `network.js` and `network-upload.js`, with sorted entries, fixed timestamps, fixed platform metadata and DEFLATE level 9. Upload the checksum-addressed archive as a versioned S3 code object and supply its immutable version to `infra/owner-b/network.cjs`. Record the source revision/tree, package-lock hash, archive hash and deployed Lambda CodeSha256. Public receipts retain hashes and outcomes; concrete project identity, ARNs, profile names, bucket/stack names and bearer URLs stay outside committed evidence.

After deploying the published parser version and its S3 invoke permission, obtain the original retained artifact stack template. Run `node scripts/network-notification.cjs original-template.json <published-parser-arn> <verified-project-id> updated-template.json`. Review a CloudFormation UPDATE change set: the notification changes without replacing the bucket; its dependent bucket policy may appear as a dynamic change. Preserve encryption, versioning, TLS policy, retention, lifecycle and unrelated notifications. Execute only the reviewed update, then allow approximately five minutes for S3 notification propagation before acceptance uploads. Updating the network stack requires updating this notification to its new published parser version before client uploads resume.

Run the committed positive, negative, exception, missing, malformed and candidate cases for each check through actual upload and hub readback. Record duplicate replay separately. `evidence=verified` means the hub validated and persisted a contract pair; synthetic or auditor origin remains synthetic or auditor and does not certify a client workload. The deployed build is pinned separately from later documentation/test revisions so its receipt does not claim an uncommitted build.

## Client capture and upload

Use a committed six-case input as the format example, then supply your own repository/commit, scope, policy thresholds and real capture provenance. Capture tool/version/origin and acquisition start/end are mandatory. Never relabel an auditor or synthetic capture as a client workload.

The connector invokes owner-b-network-upload with repository_id, bytes and SHA256 of the exact UTF-8 input file. Apply every returned signed header to the PUT; do not log the URL. Server IAM InvokeFunction authorization and repository allowlisting form the access boundary. S3 verifies the checksum and triggers the immutable-version parser automatically. After upload, query Owner D readback using that repository_id/scan_id; an accepted PUT/event alone is insufficient.

X-Ray metadata.owner_b requires capture_origin, repository_id, commit_sha, operation, destination, role, dependencies, authorization_key and check-specific metadata. No response body is requested. Existing network-evidence-event-v1 logs may carry one complete normalized route capture; ambiguous/multiple captures are unavailable until scopes are separated. Metric configurations may bind exact Count/Sum series to response-cache or connection observations only with matching policy/header snapshot metadata. Counter dimensions/window must describe the same boundary.

Reference rules follow [HTTP caching](https://www.rfc-editor.org/rfc/rfc9111.html), [HTTP encoding negotiation](https://www.rfc-editor.org/rfc/rfc9110.html), [Node Agent pooling](https://nodejs.org/api/http.html), [AWS retry guidance](https://aws.amazon.com/builders-library/timeouts-retries-and-backoff-with-jitter/) and [Protobuf encoding](https://protobuf.dev/programming-guides/encoding/). They do not justify universal format, cache or retry recommendations.
