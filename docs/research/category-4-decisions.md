## Bundle design notes (from the real webpack capture, 2026-10-10; plans not yet written)

- Emitted size is `assets[].size` (main.js 92,368 bytes) while `chunks[].size` is source size (652,679 bytes, lodash alone 545,945); use emitted asset sizes for "bytes shipped" and module sizes only for shares.
- **Trap:** in a production build, third-party modules can be concatenated into an app module: `./src/main.js + 37 modules` (100,103 bytes) nested date-fns modules. Vendor detection must read nested `modules`, not only top-level names containing `node_modules`.
- Proposed rules (to discuss in the FE-07/08/09 plans, thresholds in `context`): FE-07 initial JS share >= `min_initial_share` (0.9) and bytes >= `min_initial_js_bytes`; FE-09 an initial chunk mixing app code with >= `min_vendor_bytes` of `node_modules` and no separate vendor chunk; FE-08 a static candidate (top-level import used only inside handlers) confirmed by the imported module sitting in an initial chunk with >= `min_module_bytes`.
