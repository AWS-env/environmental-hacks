## Deviations from taxonomy

1. SRC-01 (PAPER) supports category existence and root-cause names only. The HTML text I read (first 100k chars of 111k) gives: C1 defined as "code whose results are never consumed or that repeats computation already done", C2 as call/delegation/dynamic dispatch cost "without proportional benefits", C4 as suboptimal evaluation order or preventing runtime optimization; C1 has 8 root causes, C2 has 3, C4 has 8 (matches taxonomy IDs). It does NOT, in what I read, give per-root-cause thresholds, detection methods, or per-category energy for C1/C2. C2 and C4 are "nearly absent from the highest-impact tier" (top 25% savings). C4 median saving about 307 J. Implementation-level group median 1,146 J (N=2,476) with no breakdown. So the row text "fires when / not wasteful when" and "detection signal" columns are NOT sourced from the paper as far as I could verify (the paper is described as a taxonomy plus a Python-only validation on Pie-Perf pairs).
2. The taxonomy note on C1.1 ("S01 dataset example: removing one unused heavy import gave large measured energy savings") was NOT verified: I did not locate that example in the portions read. UNVERIFIED.
3. Validation data are Python/CPython only (Pie-Perf, 21k+ pairs); statements about JS/V8 inlining or JS stack traces in rows C2.1/C4.6 are not supported by the paper text I read.
4. Rows C2.2, C4.3, C4.8, C1.7 are described by every fetched tool as style/readability or tiny gain; taxonomy itself says "likely below noise" for C1.7/C2.2 and "mostly readability" for C4.3. Consistent, but they should not be counted as energy findings without runtime evidence.
5. C4.5 "Expensive comparison" (reflection/introspection) does not match what E721/C0123 detect (type-check idiom, correctness); using those rules would be mislabelled as energy.
6. C4.6: Ruff and Perflint pages say the try-in-loop overhead is a Python < 3.11 issue (zero-cost exceptions in 3.11); the taxonomy row's "try/except cheap if rare, costly if frequent" fits, but the practical static signal (try inside loop) is weaker than the intended signal (exception frequency).
7. C1.4, C1.8, C2.1, C4.1, C4.5, C4.6 list "profiler" evidence and an S3 artifact path, but the practical Python static layer exists only for a subset; C1.4, C1.6, C1.8, C2.3, C4.1, C4.4, C4.7 have no mature tool.
8. Detection column for C2.2 says "Profiler call graph", yet the practical and cheaper detection is static (PLR6301).
9. C1.2 meaning includes "overwriting unread values" (dead store) which none of the Ruff/Pylint/CodeQL pages I read cover; Sonar S1854 is the likely owner but I could not fetch it.
10. C4.2, C4.4 rows have empty "fires when / not wasteful when" so no exemption/threshold is defined by taxonomy; any rule needs one invented by us.
