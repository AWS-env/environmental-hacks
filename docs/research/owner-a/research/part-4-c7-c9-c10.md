## Source SRC-01 check (arXiv 2604.04809)
- FETCHED https://arxiv.org/abs/2604.04809 : 12 primary energy smells, 65 root causes, 320 coded patterns from 60 papers; 21,000+ Python code pairs profiled, top 3,000 classified; 55 of 65 root causes mapped to real code; 71% of samples show multiple smells. The abstract page names no categories and no 41.6%.
- FETCHED https://arxiv.org/html/2604.04809 (first 100,000 of 111,210 chars read; last ~11k not read): Table I contains exactly the C7/C9/C10 definitions used in the taxonomy (wording matches). C7 = 41.6% of classified samples (Sec III-C), but "only third in median energy savings" (Sec IV). 15 samples where runtime improved but energy rose, all NumPy vectorization, up to +64% energy. Single hardware configuration (threat to validity). The paper presents NO detection tool (future work: "lightweight smell detector"). So every detection signal in the taxonomy (K column) is the taxonomy author's addition, not SRC-01.

## Deviations from taxonomy
1. SRC-01 presents no detection method or tool; every "detection signal" cell (linters, AST match, complexity analysis) is the taxonomy's own claim.
2. C7 "most prevalent (41.6%)" is true per Sec III-C, but the same paper says C7 ranks only third in median savings; wording "best fit for LLM patching" is not in the paper text I read.
3. Row C7.1 says "complexity analysis (hard to automate)": agreed. radon (named in the brief) measures cyclomatic complexity, not big-O; it must not be used as a C7 detector.
4. C9.1-C9.4 are marked "N" (no discussion) and mapped to static scan, but taxonomy detection signals are query logs/EXPLAIN/APM (runtime). Static detection covers only syntactic shapes (query in loop). Recommend promoting to needs-discussion, or splitting static candidate vs runtime confirmation.
5. C10.3 note is supported: SRC-01 reports NumPy vectorisation raised energy (15 samples, up to +64%).
6. C10.4 states CPython sometimes optimises `+=` and JS uses ropes; not verified from any fetched official page here (UNVERIFIED).
7. C10.5/C10.6 and many C10.2 rules are "negligible/micro" per Ruff's own docs (PERF101/102/401/403 say so); counting them as energy waste overstates benefit. C10.6 has no tool and a weak static basis.
8. Ruff PERF203 try-except-in-loop https://docs.astral.sh/ruff/rules/try-except-in-loop/ is only enforced for Python <3.11 (zero-cost exceptions) - relevant to C4.6, not in my groups, noted for cross-ref.
